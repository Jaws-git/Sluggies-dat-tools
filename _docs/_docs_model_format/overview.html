32-Byte Alignment Requirement

The Wii Broadway CPU has 32-byte cache lines and uses aligned memory operations (dcbz, paired-single loads) throughout its graphics pipeline. All raw data arrays — vertex buffers, skinning source arrays, weight arrays, index arrays, primitive lists — must begin at an address that is a multiple of 32 bytes relative to the section or region they belong to.

In observed game data, 100% of data array pointers satisfy this alignment. Violating the requirement causes the game to hang (infinite stall or bus error) rather than crash with an informative error.

When rebuilding any section, insert zero-filled padding bytes as needed between the end of fixed-size struct arrays and the start of variable-length data blobs to ensure the first data array lands on a 32-byte boundary. Each subsequent array must also be individually padded to 32 bytes before the next one begins.

data_region_start = (end_of_structs + 31) & ~31
padding_needed    = data_region_start - end_of_structs

This applies to at minimum:

  • SKN section — srcArrPtr, weightArrPtr, destIdxArrPtr, flushIndPtr
  • GPL section — position, UV, color, and normal raw data arrays; primitive list data
  • TEX section — image data and palette data buffers
