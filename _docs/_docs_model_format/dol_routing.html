main.dol Model Routing

The game finds every model block in dt_na.dat through a table in main.dol: open the file by name, seek to an offset, read a number of bytes. Nothing inside dt_na.dat says where a model lives, so relocating a model (hammerspace) only means writing the block somewhere new and repointing its DOL entry. All values are big-endian. The constants below are for the US version.

Directory pointer table

A flat array of uint32 virtual addresses at DOL file offsets 0x69C828–0x69CAD8, one per directory. Convert an address to a DOL file offset by subtracting 0x80003F00. The index into this table is the chunk number (ChunkNumber in a .sluggie; also the number in front of each export folder name).

Directory entry

Each directory is an array of 48-byte entries (12 × uint32). The index into it is the file index (FileIndex in a .sluggie). The array ends at the first entry whose word 0 is not the dt_na.dat name pointer. Each entry has three language slots of four words each, and every slot has the same layout:

Offset Type Description
0x0 uint32 File name pointer. Always 0x8067F658, the RAM address of the string "dt_na.dat"
0x4 uint32 Length of the block in bytes
0x8 uint32 Byte offset of the block inside dt_na.dat
0xc uint32 Allocation size. Equal to the length in every entry the tools write
Slot Entry offset
English (en) 0x00
Spanish (sp) 0x10
French (fr) 0x20

In the stock game all three slots point at the same data. The tools read the en slot and write all three.

What an entry points at

  • A model block (the common case). All section pointers in its header are relative to the block start, so the block can be moved as a unit.
  • An archive of several members: fileCount:u32, then fileCount u32 member offsets relative to the archive start (0 = empty slot), then the members in ascending order on 32-byte boundaries. A member's length is the distance to the next populated offset, or to the archive end for the last one. Members can be models or ANM blocks. Multi-part characters (stadium bosses, map objects) use this. Some equipment entries (bats, for example) also have a short prefix in front of the model. In a .sluggie, ModelOffset/ModelLength give the member itself, which then differs from the entry's offset/length.
  • Shared routes: several entries can hold the same offset, so the same bytes serve several chunk/file indices. Patching one of them has to repoint all of them. --untangle exports split some of these shared routes on purpose.

Relocating a model (hammerspace)

  1. Build the new block (or the whole archive, with one member replaced and the later member offsets shifted by the size change).
  2. Write it at an offset at or above BASE_SIZE (715,046,144) in the extended dt_na.dat, on a 32-byte boundary.
  3. Write the new offset and length into all three language slots of the entry, and of every entry that shares its route (length also goes into the allocation-size word).
  4. Grow the dt_na.dat size field in fst.bin (FST entry 1, size at byte 0x14) to match the extended file.

Unpatching restores the entry from the untouched input main.dol, restores the original bytes from the input dt_na.dat, and zero-fills the hammerspace range. The implementation is SluggiesTools/Hammerspace/HammerspaceHelper.py (readDolEntry, patchDolEntry, findSharedEntries, removeModelFromHammerspace) and ArchiveContainer.py.
