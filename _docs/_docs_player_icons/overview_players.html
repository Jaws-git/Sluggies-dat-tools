Mario Super Sluggers Player Icon Data Structures

Current six-character implementation reference. All binary values are big-endian. Address labels distinguish DOL runtime addresses, DOL file offsets, and icon-bank-local offsets.

This page documents the implemented data path. See Unused Character Icon Modding.md for workflow and design rationale. Historical logger and candidate-table probes are not part of the production route.

Resolved Icon Data Flow

1. Character IDUnused IDs 0x47-0x4C.
2. Color-wheel rowEnables the character with icon_valid=1.
3. Donor hookSaves the custom ID and sends donor 0x00-0x05 through stock resolution.
4. Source recordMaps character ID to a side/front resource ID.
5. Final-row hookReplaces the donor resource row with the custom row.
6. Texture pageResource UVs sample private CMPR page 0x92 or 0x93.

Critical Invariants

  • Directory EN/SP/FR offsets, lengths, and allocations must agree.
  • The expanded bank and destination are 0x20-byte aligned.
  • Private image payloads must not overlap each other or the relocated icon table.
  • Source records remain descending and retain the first/continuation marker convention.
  • Resource count, table length, and container endpoint 0x5058 grow together.
  • The resource table retains its final eight-byte tail.
  • Custom source resource IDs, resource rows, and DOL hook rows must agree.
  • Hook sites must contain exact stock words or the exact generated patch.
